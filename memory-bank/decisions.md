# Decisions — Smartchat

Ключевые технические решения и их обоснование.

## D1. Диалог — детерминированный конечный автомат, а не свободная генерация
Сценарий онбординга не отдаётся нейросети на «свободное творчество». Логика — это
явный конечный автомат (`src/orchestrator.ts`), реализующий разделы 9–10 системной
инструкции. Это гарантирует: вопросы строго по одному, явное согласие на обработку
ПД, отсутствие выдуманных цен/сроков/гарантий.

## D2. Стек: TypeScript + Express 4 + Node.js 20
TS (strict) даёт типизацию состояния диалога и интеграций; Express — минимальный
проверенный веб-фреймворк. Node.js 20 LTS выбран для совместимости с `ssh2`,
`tsx` и стабильного поведения на Linux (code-server/Beget).

## D3. Лид сначала в `data/leads.jsonl`, затем в Битрикс24
Локальный JSONL-лог — обязательный и первичный: он даёт сохранность лида даже при
сбое сети или недоступности CRM. Передача в Битрикс24 (`crm.lead.add`) — опциональная
асинхронная операция; её ошибка логируется, но не блокирует ответ боту.

## D4. YandexGPT — только для свободных вопросов вне FAQ, с mock-фолбэком
Внешняя модель подключается лишь для вопросов, не покрытых статичным FAQ. При
отсутствии `YANDEX_API_KEY`/`YANDEX_FOLDER_ID` работает mock-режим — диалог остаётся
функциональным в локальной разработке и на тестовых стендах.

## D5. Файловый контекст `memory-bank/` вместо истории чатов Cline
История чатов Cline не переносится на другой сервер, поэтому истиной о проекте
служат файлы в `memory-bank/` (projectbrief, techContext, activeContext, progress,
decisions, deployment). Cline читает их в начале каждой задачи (см. `.clinerules`).

## D6. Секреты — только в `.env`, в репозитории только `.env.example`
`.env` в `.gitignore`. В коммиты попадают только имена переменных с пустыми
плейсхолдерами и комментариями о назначении. Никаких реальных ключей, токенов,
паролей и адресов вебхуков в Git.

## D7. Доступ к code-server — через SSH-туннель или Tailscale
code-server слушает `127.0.0.1:8080` (не выставляется напрямую в интернет без
HTTPS-прокси). Доступ с планшета — по SSH-туннелю (`ssh -N -L ...`) или по
защищённой сети Tailscale. Пароль code-server генерируется один раз при установке.

## D8. Деплой на Beget — по SSH-ключу, `.env` заполняется на сервере однократно
`scripts/deploy-beget.sh` подключается ключом `~/.ssh/beget_deploy`. Хост, логин,
путь и ветка берутся из окружения или `.env`; сами секреты приложение читает из
`.env` на сервере, который заполняется вручную и в Git не попадает.

## Статус
Все решения — приняты и действуют на момент переноса разработки на code-server.
Пересмотр — только через изменение кода и соответствующего файла `memory-bank/`.
