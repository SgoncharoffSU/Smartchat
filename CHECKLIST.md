# Чек-лист ручных действий — перенос Smartchat на планшет (code-server) и Beget

> Порядок действий, которые выполняет владелец вручную (секреты и панели хостинга
> в руки Cline не передаются).

## A. Подготовка VPS (для code-server)

- [ ] A1. Арендован/выбран VPS с Ubuntu/Debian и известен IP.
- [ ] A2. Заполнены данные для входа: SSH-пользователь (root) и способ аутентификации (пароль/ключ).
- [ ] A3. На планшете установлен браузер (поддерживающий code-server): Chrome/Edge/Safari.

## B. Установка code-server

- [ ] B1. Выполнить на сервере:
  ```bash
  bash scripts/setup-code-server.sh
  ```
  (предварительно скопировать скрипт, например через git clone или scp).
- [ ] B2. Зафиксировать URL: `http://<IP>:8080` и пароль из `~/.config/code-server/config.yaml`
  (или заданный через `CODE_SERVER_PASSWORD`).
- [ ] B3. Открыть code-server в браузере планшета, авторизоваться.
- [ ] B4. Открыть папку `~/Smartchat`.

## C. Гит-доступ с code-server

- [ ] C1. Убедиться, что `git` доступен и `origin` указывает на GitHub.
- [ ] C2. При желании настроить push без ввода пароля (SSH-ключ или PAT) — по инструкции GitHub.

## D. Локальное окружение в code-server

- [ ] D1. `npm install`.
- [ ] D2. `npm run build` (получить `dist/`).
- [ ] D3. Создать `.env`:
  ```bash
  cp .env.example .env
  ```
- [ ] D4. Заполнить `.env` реальными секретами (Yandex, Битрикс24 — по необходимости).
- [ ] D5. Проверить запуск: `npm run dev` → открыть `http://<IP>:3000/demo.html`.

## E. Деплой на Beget (боевой)

- [ ] E1. Получены данные Beget: SSH-хост, пользователь, порт, путь к каталогу.
- [ ] E2. Задать переменные для `scripts/deploy-beget.sh`:
  ```bash
  export BEGET_HOST="..."; export BEGET_USER="..."; export BEGET_PATH="smartchat"
  ```
- [ ] E3. Выполнить:
  ```bash
  bash scripts/deploy-beget.sh
  ```
- [ ] E4. На Beget настроить запуск Node (по инструкции хостинга): процесс `node dist/server.js` или `npm start`.
- [ ] E5. Убедиться, что боевой виджет работает (страница клиента с кнопкой «Получить демо-доступ»).

## F. Проверка безопасности

- [ ] F1. `git status` не показывает `.env` и `data/` к коммиту.
- [ ] F2. `.env` существует только на сервере, в Git не попал.
- [ ] F3. Пароли/токены не засветились в открытых файлах репозитория.

## G. Итоговая проверка

- [ ] G1. С планшета редактируется код в code-server.
- [ ] G2. Изменения коммитятся и пушатся в `origin/main`.
- [ ] G3. Боевой бот на Beget отвечает по сценарию (раздел 9 инструкции).
