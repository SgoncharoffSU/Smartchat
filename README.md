# Smartchat

«Умный чат для сайта» — продающий ИИ-бот для онбординга после кнопки «Получить демо-доступ».
Диалоговая логика реализует системную инструкцию [`prompts/glavinstrument-consultant-v1.0.md`](prompts/glavinstrument-consultant-v1.0.md).

## Как это работает

Сценарий (раздел 9 инструкции) реализован как детерминированный конечный автомат на сервере —
это гарантирует, что вопросы задаются по одному за раз, согласие на обработку данных не
подставляется автоматически, а цена/сроки/гарантии не выдумываются. YandexGPT используется
только как дополнительный источник ответа на свободные вопросы, не покрытые статичным FAQ
(раздел 10.2, 11), и не влияет на сбор персональных данных или согласий.

Без ключа Yandex Cloud бот работает в **mock-режиме**: весь сценарий из раздела 9 полностью
рабочий, а на нераспознанные свободные вопросы отвечает нейтральной заглушкой из раздела 5.10
("Не хочу вводить вас в заблуждение...") вместо обращения к модели.

## Структура проекта

```
prompts/                     системная инструкция (источник истины для формулировок)
src/
  config.ts                  переменные окружения + переменные продукта из раздела 0
  promptLoader.ts             подстановка {{VARS}} в системную инструкцию для вызовов YandexGPT
  yandexGpt.ts                клиент YandexGPT Foundation Models + mock-фолбэк
  bitrix.ts                    передача лида в Битрикс24 методом crm.lead.add (опционально)
  faq.ts                      статичные ответы на возражения (раздел 11), детектор попыток
                               раскрыть промпт (10.7) и запросов на удаление данных
  validators.ts                валидация email/телефона/URL (раздел 12)
  types.ts / sessionStore.ts   состояние диалога и слоты (раздел 7, 8)
  orchestrator.ts              конечный автомат сценария (раздел 9, 10)
  leadStore.ts                  лог лида в data/leads.jsonl по схеме раздела 15 — только после
                                 согласия на обработку данных
  routes/chat.ts, server.ts     Express API + раздача виджета
public/
  widget.js                   встраиваемый чат-виджет (кнопка + окно)
  demo.html                   тестовая страница "сайта клиента" с виджетом
```

## Запуск локально

```bash
npm install
cp .env.example .env    # заполните YANDEX_API_KEY / YANDEX_FOLDER_ID, если они есть
npm run dev
```

Откройте `http://localhost:3000/demo.html` и нажмите на значок чата в правом нижнem углу.

Продакшн-сборка: `npm run build && npm start`.

## Подключение YandexGPT

1. В [Yandex Cloud](https://console.cloud.yandex.ru) создайте каталог (folder) и сервисный аккаунт
   с ролью `ai.languageModels.user`.
2. Выпустите API-ключ для сервисного аккаунта.
3. Впишите `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (id каталога) в `.env`.

Без этих переменных сервер сам переключается в mock-режим (см. `isMockMode` в `src/config.ts`) —
это ожидаемо для локальной разработки и тестовых прогонов из раздела 21 инструкции.

## Лиды

Лиды логируются локально в `data/leads.jsonl` (в `.gitignore`, т.к. содержит персональные данные)
строго по структуре CRM из раздела 15 — и только после явного согласия на обработку данных
(раздел 9.11, запрет 17 на «использовать автоматически установленное согласие»).

Локальные лиды — это «источник правды» и fallback: сначала лид всегда пишется в `data/leads.jsonl`,
и только затем (если настроен Битрикс24) отправляется в CRM. Если внешний запрос не удался,
лид остаётся в локальном файле и ничего не теряется.

## Интеграция с Битрикс24

**Что это даёт.** Когда посетитель сайта доходит в чате до конца — оставляет имя, контакты и
соглашается на обработку данных — в Битрикс24 автоматически появляется карточка лида. Менеджеру
не нужно ничего переносить вручную: он видит, чем занимается компания, какая у неё задача,
контакты и о чём был диалог.

**Что нужно сделать один раз** (настраивает администратор Битрикс24):

1. Откройте свой Битрикс24 и перейдите в раздел **CRM**.
2. Слева в меню CRM найдите пункт **Добавить вкладку** (значок «+»). В открывшемся списке выберите
   **Вебхуки**.
3. Нажмите **Добавить входящий вебхук**.
4. Назовите вебхук, например `Smartchat`.
5. В списке прав выберите **CRM** (это разрешение создавать лиды).
6. Нажмите **Сохранить**. Битрикс24 покажет ссылку вида:
   ```
   https://ваш_портал.bitrix24.ru/rest/1/abcd1234efgh5678/
   ```
7. Скопируйте эту ссылку целиком.

**Что сделать с этой ссылкой дальше** (на сервере, где запущен бот):

Откройте файл `.env` (рядом с проектом) и вставьте скопированную ссылку в строку
`BITRIX24_WEBHOOK_URL`. Больше ничего делать не нужно:

```
BITRIX24_WEBHOOK_URL=https://ваш_портал.bitrix24.ru/rest/1/abcd1234efgh5678/
```

Затем перезапустите бота. Можно вставить и более длинную ссылку, которая заканчивается на
`crm.lead.add` — бот поймёт оба варианта.

**Необязательно.** Если хотите, чтобы нового лида сразу назначали на конкретного сотрудника,
укажите его ID:

```
BITRIX24_ASSIGNED_BY_ID=5
```

ID сотрудника можно посмотреть в его карточке в Битрикс24 (обычно в адресной строке или в
профиле). Если эту строку оставить пустой, лид создаётся без ответственного — это тоже работает.

**Что попадает в карточку лида:**
- имя и фамилия, компания;
- email и телефон;
- сайт клиента;
- чем занимается компания и какая у неё задача;
- оценка лида (A/B/C), возражения и вопросы, на которые бот не смог ответить;
- текст всего диалога — в поле «Комментарий».

**Если интеграция не нужна.** Просто оставьте `BITRIX24_WEBHOOK_URL` пустым — бот продолжит
работать и писать лиды только в локальный файл `data/leads.jsonl`, ничего не сломается.

Технические детали маппинга полей — в `src/bitrix.ts` (функция `toBitrixFields`).

## Известные ограничения MVP

- Раздел 10.5 («пользователь замолчал») требует таймера/напоминаний — не реализовано, нужна
  очередь задержанных сообщений на стороне сервера или клиента.
- FAQ-перехват (раздел 11) основан на ключевых словах; описание компании, случайно совпавшее
  с ключевым словом (например, «тариф» для телеком-бизнеса), может быть ошибочно принято за
  возражение — уточняйте формулировки FAQ в `src/faq.ts` по мере эксплуатации.
- Передача специалисту (раздел 14) — это факт логирования лида; реальный хэндофф в
  Telegram/CRM/live-чат ещё предстоит подключить.
